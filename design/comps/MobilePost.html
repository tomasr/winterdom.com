Kondex: Teaching Claude to use it

claude llm tools

In my previous two posts, I covered how kondex builds its index and how you can query it. There's one part I haven't talked about yet, though: an index is not very useful if the LLM never thinks of using it.

If you look back at the architecture diagram in the first post, you'll notice a box labeled "kondex plugin", which contains a SessionStart hook and a skill. Let's see why both of them are there.

Starting with a skill

A skill is cheap: a folder, a description, and instructions that only load when the model decides the description matches the task. That last part is the catch.

plugin.json 
{
  "name": "kondex",
  "hooks": {
    "SessionStart":
      "./hooks/start.py"
  }
}

If you cannot tell whether a change made the model reach for your tool more often, you are guessing.

So I wrote a small harness that replays a fixed set of prompts and records whether the index was consulted before the first file read. Crude, but enough to see movement.
