In my previous two posts, I covered how kondex builds its index and how you can query it. There's one part I haven't talked about yet, though: an index is not very useful if the LLM never thinks of using it. In this post, I'd like to go over how I got Claude Code to actually reach for it.

Starting with a skill

A skill is cheap: a folder, a description, and a set of instructions that only get loaded when the model decides the description matches the task at hand. That last part is the catch — the description has to win against everything else competing for attention.

.claude-plugin/plugin.json 
{
  "name": "kondex",
  "description": "Symbol and declaration lookup for large repos",
  "hooks": {
    "SessionStart": "./hooks/session_start.py"
  }
}

If you cannot tell whether a change made the model reach for your tool more often, you are not iterating — you are guessing.
